Is our design system AI-ready?

DescripciónDescription

Un marco de auditoría de seis dimensiones para evaluar cómo un sistema de diseño de herramientas mayoristas puede apoyar flujos asistidos por IA.A six-dimension audit framework to assess how a wholesale-tools design system can support AI-assisted workflows.

Definición del problemaProblem statement

La IA necesita tokens, APIs, documentación y estructuras coherentes; las diferencias entre diseño y código y la falta de gobernanza pueden generar errores y divergencias.AI needs consistent tokens, APIs, documentation, and structures; design–code mismatches and missing governance can lead to errors and drift.

Qué creéWhat I created

Una guía de evaluación de 0 a 5 para arquitectura de tokens, APIs de componentes, paridad diseño–código, estructura, gobernanza y preparación de flujos con IA.A 0–5 assessment guide covering token architecture, component APIs, design–code parity, structure, governance, and AI workflow readiness.

Aprendizajes claveKey learnings

Pendiente: el borrador aún no incluye los hallazgos al aplicar la auditoría ni las acciones realizadas.Pending: the draft does not yet include findings from applying the audit or the actions taken.

My role

Lead product designer of the design system audit for wholesale tools.

Seis dimensiones para evaluar la preparación para la IA e identificar dónde mejorar.Six dimensions to assess AI readiness and identify where to improve.

Cómo puntuarHow to score

Puntúa cada dimensión de 0 a 5: 0 inexistente · 1–2 incipiente o informal · 3 parcialmente establecida · 4–5 coherente, documentada y mantenida.Score each dimension from 0 to 5: 0 absent · 1–2 early or ad hoc · 3 partially established · 4–5 consistent, documented, and maintained.

Las seis dimensionesThe six dimensions

01 / Arquitectura de tokens01 / Token architecture

Tokens semánticos y jerarquizados, disponibles en formatos legibles por herramientas y con documentación actualizada.Semantic, tiered tokens in tool-readable formats, backed by current documentation.

02 / APIs de componentes02 / Component APIs

Props, variantes y estados coherentes y documentados para generar código fiable.Consistent, documented props, variants, and states for reliable code generation.

03 / Paridad diseño–código03 / Design–code parity

Nombres, tokens y variantes alineados entre Figma y código, con un proceso de sincronización.Matching names, tokens, and variants across Figma and code, with a process to keep them in sync.

04 / Estructura y capas04 / Structure and layers

Capas con nombres descriptivos, Auto Layout y una jerarquía clara de archivos.Descriptive layer names, Auto Layout, and a clear file hierarchy.

05 / Gobernanza y contribución05 / Governance and contribution

Responsables definidos y procesos claros para contribuir, versionar y comunicar cambios.Clear ownership and processes for contributions, versioning, and communicating changes.

06 / Flujos de trabajo con IA06 / AI workflows

Al menos un flujo repetible, documentación legible por máquinas y límites de confianza compartidos.At least one repeatable workflow, machine-readable documentation, and agreed boundaries for trusting AI.

Your score

Score all six dimensions and add them up. The result is a map of where the leverage is, not a grade.
